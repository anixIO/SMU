# СМУ · Контроль усталости

СМУ отслеживает видимые признаки сонливости по изображению с камеры. Браузер показывает состояние, долю времени с закрытыми глазами и динамику сеанса. MediaPipe и OpenCV обрабатывают кадры на машине, где запущен сервер. Изображения не сохраняются. В журнал и CSV попадают только показатели и предупреждения.

Система работает с видимыми признаками. Освещение, положение камеры и видимость лица влияют на результат. СМУ не заменяет отдых или профильную диагностику.

## Запуск

Нужны Python 3.11 и браузер с доступом к камере.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python web.py
```

Если команда `python` недоступна, используйте `./.venv/bin/python web.py`. В Windows окружение активируется через `.venv\Scripts\activate`.

1. Откройте <http://127.0.0.1:8000>.
2. Нажмите **Начать наблюдение**, разрешите доступ к камере и смотрите прямо до конца калибровки. Моргать можно.
3. Нажмите **Завершить**, чтобы выключить камеру. Отчёт доступен по кнопке **Скачать CSV**. История сеанса раскрывается под камерой.

Для голосовых оповещений нужен русский голос браузера или системы. Если голос недоступен, приложение использует звуковой сигнал. Проверить звук можно кнопкой **Проверить**.

Оконная версия работает отдельно. Нажмите Esc для выхода.

```bash
python main.py
```

### iPhone и другие телефоны

В VS Code откройте **Порты → Перенаправить порт**, введите `8000` и скопируйте полученный HTTPS-адрес. Запустите или перезапустите сервер с этой ссылкой вместо примера.

```bash
SMU_TUNNEL_URL='https://<адрес-из-вкладки-порты>' ./.venv/bin/python web.py
```

На телефоне откройте ссылку в браузере и разрешите камеру. Ноутбук, сервер и перенаправление должны оставаться включёнными. Приватная ссылка потребует входа под тем же аккаунтом. Для личной проверки этого достаточно. Открытый порт даёт доступ к экрану наблюдения всем, у кого есть ссылка. [Инструкция VS Code](https://code.visualstudio.com/docs/debugtest/port-forwarding).

Сервер разработки рассчитан на локальный запуск или временную проверку. Он обрабатывает до трёх независимых сеансов в одном процессе. Сеанс после 90 секунд без кадров освобождается при следующем обращении к наблюдению. На телефоне кадры идут по HTTPS через туннель на сервер.

## Администрирование

Создайте учётную запись в отдельном терминале. Хранилище SQLite и таблицы создаются автоматически.

```bash
./.venv/bin/python web.py createsuperuser
```

Откройте <http://127.0.0.1:8000/admin/>. Панель доступна по локальному адресу с учётной записью администратора. Здесь можно посмотреть сводку за 7 дней, историю сеансов, долю кадров с лицом и предупреждения. Из таблицы скачиваются CSV завершённых сеансов. Старые веб-отчёты доступны в архиве. Предупреждения можно отмечать как ложные и снимать отметку.

Базовые значения лежат в `config.yaml`. Изменения из панели записываются в отдельный `config.local.yaml` и применяются при следующем запуске сеанса. Форма проверяет диапазоны и связь между окном PERCLOS и временем разогрева. Кнопка **Вернуть базовые** удаляет локальное переопределение. Метрики, база и отчёты хранятся в `output/`. Эти файлы исключены из Git. Часовой пояс панели можно задать переменной `SMU_TIME_ZONE` (по умолчанию `Asia/Yekaterinburg`).

## Распознавание

MediaPipe определяет точки лица. СМУ вычисляет открытость глаз (EAR), рта (MAR) и положение головы. Короткая калибровка запоминает медианную открытость глаз и положение головы в начале сеанса. Если подходящих кадров недостаточно, применяется базовый профиль.

Длительное закрытие глаз или высокая доля времени с закрытыми глазами вызывают предупреждение о сонливости. Устойчивый наклон, поворот и возможный зевок отображаются как отдельные сигналы. Неопределённые углы показываются прочерком. Если лицо пропало или слишком далеко, оценка прерывается.

### Проверка EAR на реальных видео

Запустите сравнение на архиве [Eyeblink8 от авторов](https://www.blinkingmatters.com/research).

```bash
./.venv/bin/python -m tools.benchmark_eyes /путь/к/eyeblink8.zip
```

Сравниваются фиксированный порог EAR 0,22 и калиброванный порог с разными границами закрытия и открытия. Оба варианта получают одни и те же точки лица. В проверку входят кадры после начала оценки, где разметка подтверждает полностью закрытые оба глаза или отсутствие моргания при видимых глазах. Обрабатывается каждый третий кадр в восьми видео. На 22 817 кадрах с результатом получены следующие значения.

| Измерение | Порог 0,22 | Калибровка |
| --- | ---: | ---: |
| Открытые глаза правильно распознаны | 90,08% | 95,98% |
| Открытые глаза ошибочно распознаны как закрытые | 2 208 | 895 |
| Полностью закрытые глаза правильно распознаны | 567 из 567 | 563 из 567 |

Калибровка уменьшила число ошибок на открытых глазах на 59,5%. Четыре кадра с закрытыми глазами пропущены. В одном из восьми видео стало больше ошибок на открытых глазах. Проверка измеряет распознавание состояния глаз на этой выборке. Для оценки сонливости и предупреждений нужны отдельные размеченные данные.

Для следующего эксперимента подходят [UTA-RLDD](https://sites.google.com/view/utarldd/home) с метками состояния целого видео и [FatigueView](https://github.com/FatigueView/fatigueview/tree/main/dataset) с разметкой зевков и другими данными. Версия использует калибровку и правила. Видео для испытаний и веса сторонних моделей в репозиторий не входят.

## Проверки

```bash
./.venv/bin/python web.py check
./.venv/bin/python -m unittest discover -s tests -v
node tests/test_frontend.js
```

Автоматические проверки покрывают время событий, калибровку, изоляцию сеансов, HTTPS и CSRF, права администратора, проверку формы настроек и выгрузку отчётов. Команда с Node.js проверяет клиентскую логику без камеры.
